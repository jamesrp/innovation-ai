Implement a complete, deterministic Innovation game engine in Python from the attached rules and card list. The immediate goal is to support reliable games between basic agents—random, scripted, heuristic, or human-controlled—while keeping the architecture suitable for later self-play and PyTorch-based ML research. Keep the engine independent of any ML framework and choose language-appropriate abstractions.

Model gameplay as an explicit state machine. Every point where a player must choose something, including choices nested inside card effects, should produce a first-class decision containing the acting player, their observable state, and the legal actions. Applying one action should deterministically advance the engine to the next decision or terminal result; avoid arbitrary callbacks from card implementations into agents.

Strictly separate the authoritative game state from the player-visible observation supplied to an agent, so hidden hands, deck order, and other private information cannot leak. Represent actions as stable, structured data with semantic identifiers rather than display strings or list indices. Support deterministic replay, versioned serialization/logging, and strong rule invariants and tests.

Expose a simple single-decision agent interface now, but design the runner and protocol so many games waiting on decisions can later be collected and evaluated as a batch by an external model process. Keep game execution, observation construction, agent selection, logging, and evaluation loosely coupled so future encoders, neural architectures, and self-play pipelines can change without rewriting the rules engine.
